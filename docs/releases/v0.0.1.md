# LZY 0.0.1 — Language Foundation

**Complex logic. Simple code.**

The first working version of LZY. The core language runs, is specified, and
is tested. This is an early release: it is a good time to read LZY, try it
and argue with its design, and not yet a good time to build something
important on it.

---

## What LZY is

A programming language built around one rule:

> **Less syntax, not less understanding.**

```lzy
say "Hello World"
```

```lzy
numbers = [10, 20, 30, 40]

total = 0
for number in numbers
    total = total + number

say "Total:", total
```

LZY removes ceremony, not meaning. There are no semicolons, no braces and no
boilerplate — but also no hidden conversions, no truthiness, and no guessing
about what you meant.

## Installing

Needs **Python 3.9 or newer** and nothing else. The interpreter has no
third-party dependencies.

```bash
pip install lzy_lang-0.0.1-py3-none-any.whl
lzy --version
lzy repl
```

Or from source:

```bash
git clone https://github.com/rishav9713/lzy
cd lzy
pip install -e .
```

## What is in this release

**The language**

- Case-insensitive names — `total`, `Total` and `TOTAL` are one name. Folding
  is Unicode NFKC then full case folding, and your own spelling is kept for
  error messages.
- Indentation-based blocks, spaces only.
- Seven types: `number`, `text`, `truth`, `nothing`, `list`, `map`,
  `function`.
- **One numeric type.** `6 / 2` is `3`, and `4.0 == 4` is `true`.
- `if` / `else if` / `else`, `while`, `for ... in`, `break`, `continue`.
- Functions with recursion, mutual recursion, closures and first-class use.
- Lists and maps, including `map.name` access and `copy()`.
- 33 built-in functions.
- `say` and `ask`. Anything `ask` reads is data, never code.

**Tools**

- `lzy run`, `lzy check`, `lzy repl`, `--safe`, `--debug`, and running a
  program piped in on standard input.
- A REPL that keeps names between lines and collects indented blocks.

**Documentation**

- A complete specification (`SPEC.md`) and a formal grammar.
- A course from the first program upward (`docs/learn/`, levels 1–5).
- 22 runnable examples, each with its output recorded and checked by a test.

## Error messages are a feature

```
Type error in totals.lzy, on line 3.

'+' cannot add a number and text.

    say total + name
              ^

LZY keeps numbers and text apart so that '+' always means the same thing.
Use number(...) to add them as numbers, or text(...) to join them as text.

Maybe you meant:

    total + number(name)
```

Every error answers four questions: what happened, where, why, and how to
fix it. LZY never shows a Python traceback to someone writing LZY.

## Design decisions worth knowing

These will surprise people who come from other languages, so they are stated
plainly. Each is argued in `docs/OWNER_DECISIONS.md`.

- **No truthiness.** `if count` is an error. Write `if count != 0`.
- **No implicit conversion.** `1 + "1"` is an error.
- **Blocks do not create scopes.** A value set inside an `if` is still there
  afterwards.
- **Map keys are data.** `map["Name"]` is always exact; only `map.name` falls
  back to case-insensitive matching, and it refuses to guess between two
  matching keys.
- **Tabs are refused** in indentation, because a beginner cannot debug what
  their editor renders differently.

## Known limitations

Named so nobody has to guess. All are on the roadmap.

- No error handling — a program cannot recover from an error.
- No modules; one file per program.
- **No file, network or process access at all.**
- No anonymous functions, no compound assignment (`+=`), no string
  interpolation.
- `sort` takes no comparison function.
- A keyword cannot follow a dot: write `question["ask"]`, not
  `question.ask`.
- A `while true` loop runs forever; there is no time limit.

The full list is in `SPEC.md` §14 and `PROJECT_STATUS.md`.

## Security

- No file, network or process access exists in the language, so a program has
  no route to the host.
- Limits on source size, nesting, recursion and output, enforced in one place
  and tested against hostile input. A tighter profile is available with
  `--safe`.
- `random_number` uses the operating system's cryptographically secure
  generator.
- Zero runtime dependencies, so there is no third-party supply chain.

**LZY is not a sandbox.** There is no time or memory limit. Do not run
untrusted LZY without real isolation. See `SECURITY.md`.

Report vulnerabilities privately through GitHub's security advisories, not
as public issues.

## Testing

- **1156 tests pass**, including 420 fuzz cases.
- 91% line and branch coverage.
- Every example's output is recorded and compared on every run.
- Every ```lzy block in the documentation is parsed by a test, and every
  block shown as a mistake is checked to still be one.

Six bugs were found and fixed during the build, each with a regression test.
One of them was a genuine crash: comparing a list that contained itself
overflowed the C stack and killed the process.

## Platforms

Pure Python, so LZY runs anywhere Python 3.9+ does.
